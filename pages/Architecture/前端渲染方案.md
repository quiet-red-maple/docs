

### 项目架构模式

#### 1. SPA（单页应用）

特点：客户端渲染，首屏加载后由 JS 动态渲染
代表框架：React、Vue、Angular
优点：交互流畅、体验好
缺点：SEO 差、首屏慢

#### 2. MPA()

特点：服务端渲染，每次页面跳转都由服务器返回完整 HTML 文档，浏览器整页刷新
代表框架：传统 PHP + Smarty、JSP、ASP.NET、Django（服务端模板）
优点：
SEO 友好（搜索引擎可直接抓取完整 HTML 内容）
首屏加载快（服务器直接返回内容，无需等待 JS 执行）
开发门槛低（无需复杂的前端工程化）
缺点：
每次跳转都整页刷新，体验不流畅
前后端耦合紧密，不利于团队分工和接口复用
服务器压力大（每次请求都要重新渲染完整页面）

#### 3. 混合架构（Hybrid / 微前端）

特点：MPA 和 SPA 共存，不同页面按需选择渲染方式，首屏走 SSR 提升加载速度和 SEO，后续交互走 SPA 保证流畅体验
代表框架：Next.js、Nuxt.js（首屏 SSR + 后续 SPA）、qiankun、Module Federation（微前端）
优点：
SEO 友好（关键页面服务端渲染，搜索引擎可抓取）
首屏加载快（服务器直接返回内容，无需等待 JS 执行）
交互流畅（页面切换走 SPA 逻辑，无整页刷新）
灵活度高（不同模块可用不同技术栈，适合多团队协作）
缺点：
架构复杂度高（需要同时维护服务端和客户端两套渲染逻辑）
开发成本高（需要掌握 SSR、水合、微前端等进阶技术）
调试困难（服务端和客户端环境差异导致问题定位复杂）
部署运维复杂（需要 Node.js 服务端环境，不像纯静态托管那么简单）

### 一、核心渲染模式

#### 1. CSR（客户端渲染）

定义：服务器返回一个空壳 HTML，浏览器下载 JS 后，在客户端执行 JS 生成内容。
特点：首屏慢，SEO 差，但后续交互流畅。
代表：纯 Vue/React 默认模式。

#### 2. SSR（服务端渲染）

定义：服务器直接跑 JS 框架，把组件渲染成完整 HTML 字符串返回给浏览器。
特点：首屏快，SEO 好，但服务器压力大，每次请求都要重新渲染。
代表：Next.js、Nuxt.js 的 SSR 模式。

#### 3. SSG（静态站点生成）

定义：构建时（build time）​ 就把所有页面生成好静态 HTML 文件，部署到 CDN 上。用户访问时直接返回现成的文件。
特点：比 SSR 还快（因为不用实时渲染），SEO 极好，成本极低（不需要服务器动态计算）。
代表：VuePress、Astro、Next.js 的 export 模式。
适用：博客、文档站、官网等内容不变或更新不频繁的站点。

#### 4. ISR（增量静态再生）

定义：SSG + SSR 的结合体。先静态生成页面，但设置一个"过期时间"。过期后，第一次请求会触发服务器重新渲染并更新静态文件，之后的请求又走静态文件。
特点：兼顾了静态的速度和动态的实时性。
代表：Next.js 的 revalidate 属性。
适用：电商商品页（价格变动不频繁但需要更新）。
